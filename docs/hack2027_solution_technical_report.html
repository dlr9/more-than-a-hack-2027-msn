2. 任务理解与设计原则

提交文件需要针对战术视频的每一帧输出一个标签：

  • H：主队控球。
  • A：客队控球。
  • D：死球或比赛未处于活球控球状态。
  • X：不评分区间或主动弃权。

当前实现遵循以下原则：

  1. 先建立可信下限。不修改官方 starter/baseline.py，在独立模块内精确复现。
  2. 每次增强都可回退。reference、heuristic、model/final 是独立模式。
  3. 公开五分钟不参与选参。它只适合排查帧对齐、主客映射和输出异常。
  4. 外部数据按比赛拆分。禁止同一比赛的帧泄漏到训练集和验证集。
  5. 避免供应商特有身份特征。模型不使用球员 ID、号码、球队名称或固定进攻方向。
  6. 逐帧概率与时序约束分离。模型负责估计概率，Viterbi 负责生成连续 possession。

5. 代码模块说明：每部分做什么、怎么使用

solution/run.py

职责：统一推理入口。读取配置和目标数据，根据模式调用 reference、heuristic 或模型管线，最后写出 CSV、标签计数和 SHA256。

使用：python -m solution.run --mode ... --out ...

保护：final 模式会拒绝未通过晋级门槛的模型。

solution/atd.py

职责：解析 ATD XML/TXT；映射 track slot；按视频帧对齐；计算逐帧空间特征；在原始球速缺失时用连续球位置重建速度。

输入：metadata XML、raw TXT、帧数、球场尺寸、fps。

输出：FeatureBatch，包含特征数组与最近球队代码。

solution/features.py

职责：提供与数据供应商无关的统一特征计算；同一字段可用于目标 ATD、SkillCorner 和 Metrica。

核心：spatial_features() 计算单帧特征，add_temporal_features() 计算 0.2/0.5/1 秒窗口特征。

solution/heuristic.py

职责：实现官方多数投票和规则增强，包括短片段清理、缺球弱先验、重新开球检测和 Smart Tagging 覆盖。

使用：通常由 run.py --mode reference/heuristic 调用，不需要单独运行。

solution/external.py

职责：把 SkillCorner 和 Metrica Game 3 转成共同 NPZ 协议，并保存比赛级标签、半场和最近球员 baseline。

SkillCorner：possession.group 提供 H/A；phases-of-play 提供 alive/dead 候选。

Metrica：仅作为跨供应商高置信度检查。

solution/train.py

职责：外部数据准备和训练的命令入口。

子命令：prepare-skillcorner、prepare-metrica、fit。

solution/modeling.py

职责：训练两个分类器、选择概率模型、选择 Viterbi 参数、与 nearest-player + smooth50 比较、执行晋级门槛、保存模型和报告。

输出：alive.joblib、home.joblib、training_report.json。

solution/decoder.py

职责：把两个概率头组合为 H/A/D 发射概率，并在每个半场独立运行 Viterbi。

保证：块外默认 X，状态不会跨越中场。

solution/submission.py

职责：统一输出 frame,label CSV、检查标签只含 H/A/D/X、计算 SHA256。

solution/config.json

职责：集中管理可调参数，避免常数散落在源码。

内容：smooth50、短片段 12 帧、重新开球 2 m/s、特征窗口、随机种子、模型网格和 Viterbi 网格。

tests/test_solution.py

职责：覆盖帧映射、米制距离、主客映射、缺球、短片段、Viterbi、比赛拆分、CSV 契约和训练冒烟测试。

environment-solution.yml / requirements-solution.txt

职责：固定 Python 和主要依赖版本，保证三名队员的训练与推理环境一致。

6. 统一逐帧特征协议

模型特征不依赖具体球员或球队身份。字段按类别如下：

类别主要字段用途
球观测ball_visible、ball_speed_mps、ball_speed_missing区分可靠球运动、缺球和速度重建。
最近距离双方第 1/2/3 名球员距离、前三人平均距离判断哪一方在局部空间内更可能控制球。
距离差nearest_distance_margin_m表示主客队最近球员相对优势。
局部密度双方在 1/2/3/5/10 米内人数描述争抢、压迫和局部人数结构。
可见与速度双方可见人数、双方 5 米局部平均速度处理广播视野差异和局部动态。
场地边界球到四条边界的米制距离辅助识别边线、底线和潜在死球。
时间窗口0.2/0.5/1 秒可见率、距离均值、球位移让单帧模型观察短期运动上下文。
域适配原则：不使用 player ID、球衣号码、具体球队名称或固定进攻方向。match ID 只用于比赛级拆分和审计，不作为训练特征。

7. 监督模型、时序解码与晋级机制

7.1 两个概率模型

P(alive)

训练 alive/dead 分类器。SkillCorner 半场内、未被 phase 覆盖的部分作为 dead 候选；所有 phase 边界前后 1 秒从训练中排除。

P(home | alive)

只使用 alive 且 possession.group 已知的帧训练。内部标签为 home=1、away=0、未知=-1。

两者均使用固定版本的 HistGradientBoostingClassifier，使用逆类别频率 sample weight 和随机种子 2027。

7.2 固定模型网格

max_leaf_nodes:      15, 31
learning_rate:      0.05, 0.1
l2_regularization:  0, 1
max_iter:           300（启用 early stopping）

概率模型先按 validation balanced accuracy 选择，log loss 作为次要判断；随后再独立选择 Viterbi 参数，避免把所有参数放在一个大搜索中。

7.3 三状态发射概率

P(D) = 1 - P(alive)
P(H) = P(alive) × P(home | alive)
P(A) = P(alive) × (1 - P(home | alive))

7.4 Viterbi 网格与选参顺序

  • H↔A 转移惩罚：1、2、3、4、5。
  • H/A↔D 转移惩罚：0.5、1、2、3。
  • 优先平均 spellF1；同分时依次比较 macroF1、预测片段数和较小惩罚。
  • 每个半场独立解码，不允许 possession 跨越中场。

7.5 自动晋级门槛

  1. SkillCorner validation 平均 spellF1 相比 nearest-player + smooth50 至少提升 0.02。
  2. 至少 70% 的 validation 比赛 spellF1 不下降。
  3. Metrica Game 3 高置信 H/A 帧 macroF1 不得下降超过 0.02。
  4. 三个条件满足后设置 promoted=true，才评估 SkillCorner test。

8. 评估指标与五分钟公开真值

macroF1

分别计算 H、A、D 的逐帧 F1，再等权平均。它回答“每一帧的类别是否正确”。

macroF1 = (F1_H + F1_A + F1_D) / 3

spellF1_mean

将连续 H/A/D 看成 possession spell，通过时间 IoU 一对一匹配。它重点惩罚抖动、片段拆分/合并和切换时机错误，也是更关键的排名指标。

8.1 五分钟公开区间

公开真值包含 7,500 个评分帧，即 25 fps 下的 300 秒。当前官方 scoreboard 中：

提交公开 macroF1公开 spellF1_mean说明
baseline_smooth500.6207330.325581官方现有评分。
reference_smooth500.6207330.325581与官方文件字节相同，因此分数严格相同。
heuristic_v1未计算未计算当前只通过 validator 和确定性检查。
不可用公开五分钟选版本。官方 smooth125 在公开五分钟 spellF1 更高，但官方公布的全场表现低于 smooth50。这说明 17 个左右的公开 possession 无法可靠排序模型。即使未来计算 heuristic 的公开分数，也只能用于管线检查。
