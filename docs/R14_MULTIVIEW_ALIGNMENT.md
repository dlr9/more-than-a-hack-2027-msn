# R14 multiview and camera prototype

This is an array-level minimal implementation, not a trained video detector or a validated real-video system. View inputs need normalized fixed-pitch coordinates, metre pitch dimensions, frame/period/video time, canonical teams, shot/replay masks, homography validity/reprojection error, observed-ball mask and optional grounded-ball and independent match-clock anchors. It cannot manufacture missing calibration, shot labels or a match clock from pixels. All off/uncalibrated paths preserve the original ball array exactly.

Ball-free player fingerprints are permutation/team-exchange invariant. Mutual nearest-neighbour matches, ambiguity rejection, shot/period/gap separation, monotonic/cycle constraints and local affine offset/drift fitting precede fusion. An independent clock or shared ball is required in addition to player shape. A video timestamp is NOT an independent match clock. Replay/invalid H/contradictory clock/ambiguous geometry is rejected. No matching through unconstrained gaps, no ownership inference, no forced interpolation. Unknown airborne/grounded status forbids ground-plane ball filling.

V1 negative control caught a real bug: wrong ball coordinates conflicted on shared frames yet still filled 67 missing frames. V2 quarantines the entire conflicting source shot; old observed coordinates are never overwritten. V1 report and protocol remain in Git. V2 is a structural repair, not threshold search against real matches.

V2 synthetic scene: 600 reference frames; source starts at 2 seconds with 1.02 drift. 362 accepted correspondences, zero wrong accepted matches within the declared one-frame tolerance, maximum error .46 reference frame; 67/80 missing frames restored (67/600 overall coverage gain). Team/slot permutations agree. Replay, wrong clock, wrong-time geometry, invalid H and missing both anchor families reject. With both balls missing and a good clock, alignment can work but no ball is fabricated. Conflicting ball scene keeps alignment yet restores zero frames. These are known-scene tests with shared generative geometry and are not estimates of real-world false-match rates or external confidence calibration.

Camera proxies from homography: projected pitch-grid median movement, inverse image-centre location and scale change. Fixed-camera negative has zero pan; synthetic 50 px/s pan is recovered; abrupt cut is detected/reset. Proxies are camera motion, not ball position or player attention. No paired public multi-camera/H sequence with complete H/A/D labels was available in the verified local corpus, so real incremental information and possession impact remain NOT TESTED.

Entry points: multiview.contracts.View → multiview.align.align → multiview.fuse.fuse (enabled=False, validated=False by default); multiview.camera.camera_proxies. Run scripts.research_r14_multiview for the reproducible synthetic fixture. See frozen V1/V2 protocol hashes. Any local authorized deployment needs its own lawful data adapter and independently calibrated tolerances; these synthetic defaults must not enter competition inference.
